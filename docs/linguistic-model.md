# 규칙 모델과 규범 분석 범위

이 모델은 신경망 학습 모델이 아니라, 직접 작성한 어휘 대응과 적용 조건을 실행하는 결정적 규칙 모델이다. 완전한 형태소 분석기·맞춤법 검사기·의미 번역기는 아니다. 현재 모델은 0.1.0이며, 데이터의 개수는 앱과 평가 도구가 실제 `RULES` 배열에서 읽는다.

## 참고 규범과 자료 접근

| 문헌 | 검토 대상 | 현재 확인 상태 |
| --- | --- | --- |
| 국립국어원 한글 맞춤법 제10–12항 | ㄴ·ㄹ 계열 두음 법칙과 예외 | 참고 문헌 등록. 이 환경의 원문 요청은 proxy 403으로 실패 |

| 조선말규범집(2010), 맞춤법·띄여쓰기 | 첫소리, 합성어, 외래어, 의존 명사 표현 | 위키문헌 전사본 참고 주소 등록. 공식 원본·최신 판본 대조 미완료 |
| 편집 남북 어휘 대응 목록 | 대상·뜻·사용역 차이 | 직접 작성. 사전 전재가 아니며 전문가 독립 검수 전 |

원문 접근 실패를 자료를 읽은 것처럼 보고하지 않는다. 도메인 `korean.go.kr`, `www.korean.go.kr`, `ko.wikisource.org`를 환경 설정 초안에 추가했지만, 초안 저장은 현재 네트워크 변경이 아니다. 원문 접근이 가능해지면 각 항목의 정확한 용례·출처·판본을 대조해야 한다. 규범집 전체를 학습하거나 완벽히 파악했다고 주장하지 않는다.

## 규범 차이의 구현 원칙

### 두음 법칙
남측에서 한자어 첫소리의 ㄴ/ㄹ이 탈락하거나 ㄴ으로 바뀌는 범주와 북측 첫소리 표기를 대응한다. 예: 노동/로동, 여자/녀자, 여행/려행, 역사/력사, 이론/리론, 냉면/랭면. 모든 ‘여→려’, ‘이→리’, ‘노→로’를 전역 치환하면 여름·이름·노래 등 공통어가 손상된다. 그래서 전체 어휘와 등록된 합성어를 사용한다. 등록되지 않은 복합어는 그대로 둔다.

한자 뜻의 구별도 중요하다. 노력(努力)은 북측에서도 노력이며 로력(勞力)의 남측 대응인 노력과는 다르다. 입장(入場)/립장(立場), 유학(儒學)/류학(留學), 양식(樣式)/량식(糧食), 이상(以上)/리상(理想), 이성(異性)/리성(理性) 역시 구별해야 한다. 현재 모델은 제한된 문맥 단서가 있는 문장에서만 중의적인 표준어를 바꾼다. 문장 경계를 넘어 단서를 사용하지 않는다. 이것은 의미 분석의 완전한 해결이 아니다.

### 사이시옷과 합성어
남측 사이시옷 표기를 등록 합성어별로 대응한다. 나뭇잎/나무잎, 햇빛/해빛, 찻잔/차잔 등. 받침 ㅅ을 전부 없애지 않는다. ‘귀가’(歸家)와 ‘귀가’(귓가의 북측 표기), ‘귀속’(歸屬)과 귓속, ‘초대’(招待)와 촛대, ‘바다가 넓다’의 바다+가와 바닷가의 북측 표기는 북측→남측에서도 중의적이다. 등록 문맥이 없으면 보존한다. 위/웃의 대응은 일부 등록 단어만 구현한다.

### 외래어와 어휘
콤퓨터, 라지오 등은 등록 표기 대응이다. 옥수수/강냉이, 채소/남새, 도시락/곽밥 등은 어휘 대응이며 문맥 확인 표시를 한다. 표기 규칙과 어휘 치환은 따로 끌 수 있다. ‘친구/동무’는 사회적 사용역이 완전히 같지 않다. ‘아파트/살림집’처럼 대상 범위가 같지 않은 표현과 근거가 불확실한 인터넷 유행 번역은 기본 사전에 넣지 않는다.

일부 대응은 가역적이지 않다. 휴대전화와 핸드폰은 둘 다 손전화로 바뀌며 역방향 대표형은 휴대전화다. 남측의 오징어→북측 낙지, 남측 낙지→북측 서해낙지처럼 서로의 표면형이 겹치는 경우 같은 방향으로 결과를 다시 변환하면 달라질 수 있다. 모델은 한 번의 변환 안에서 결과를 다시 처리하지 않는다. 모든 문장의 왕복 동일성을 보장하지 않는다.

### 띄어쓰기와 문법
남측 의존 명사 ‘수’의 띄어쓰기와 북측 등록 표현을 대응한다. 예: 할 수 있습니다/할수 있습니다. 등록한 동사·어미 조합 외에는 추정하지 않는다. 남북 띄어쓰기 규범의 전체 적용, 다른 의존 명사·단위 명사·복합명사의 자동 분류는 미구현이다. 경어·어미·문체를 임의로 다시 쓰지 않는다.

조사 은/는, 이/가, 을/를, 과/와, 으로/로, 아/야는 변경 단어의 종성에 따라 조정한다. 으로/로는 ㄹ 종성 예외를 고려한다. 조사 목록과 일부 하다 활용형은 제한적으로 등록한다. 완전한 형태소/활용 분석은 아니다.

## 알고리즘과 개인정보
1. 입력 50,000자 제한, NFC 정규화. 정규화된 원문에 대한 UTF-16 위치를 반환한다.
2. URL, 이메일, Markdown 코드, 사용자 보호어로 시작하는 어절을 보호한다.
3. 첫 글자별 후보 인덱스에서 긴 표현부터 검사한다.
4. 어절 경계, 허용 조사/활용, 문맥, 보호 구간 충돌을 검사한다.
5. 겹치지 않는 규칙을 한 번만 적용한다. 원문/결과 세그먼트와 근거를 반환한다.
6. React 텍스트 노드로 표시한다. 사용자 문자열을 HTML로 실행하지 않는다.

입력·결과를 서버로 보내거나 로컬 저장소에 자동 보관하지 않는다. 앱 코드·글꼴 요청 외에 변환용 네트워크 요청은 없다. 데스크톱 렌더러는 Node 접근이 없으며 외부 네트워크를 차단한다.

## 90% 목표의 검증
자체 테스트와 16개 회귀 예문은 개발 기능 확인이며 일반 언어 정확도의 증거가 아니다. 독립 코퍼스는 규칙 개발에 쓰지 않은 원문과 전문가가 확인한 정답 쌍이어야 한다. 양방향 각각 문장 완전 일치율 ≥ 90%를 목표로 삼고 문자 편집 오류율도 보고한다. 표본 수, 분야, 어휘 분포, 고유명사 포함 여부, 판본을 함께 공개해야 한다. 정확도 수치만 있고 코퍼스가 없으면 목표 달성으로 인정하지 않는다.

```sh
npm run evaluate -- --regression
npm run evaluate -- /path/to/reviewed-corpus.jsonl report.json
```

JSONL 각 줄: `{ "id": "unique-id", "direction": "south-to-north", "input": "원문", "expected": "검수된 정답" }`. 반대 방향은 `north-to-south`. 빈 코퍼스, 중복 ID, 잘못된 방향·타입을 거부한다. 문장별 2,000자 제한. 방향에 표본이 없으면 해당 비율은 null이다. 현재 독립 코퍼스와 언어 전문가 검수가 없으므로 90% 달성은 미검증이다.

## 향후 정확도 향상 경로
원문 규범 대조 → 어휘별 용례와 의미 ID 추가 → 독립 양방향 정답 코퍼스 확보 → 실패 분석 → 활용/합성어 등록 확장 → 형태소 분석기 연결 순서로 진행한다. 데이터 라이선스를 확인한 자료만 포함한다. 적용 범위를 넓히기 위해 오변환을 허용하는 전역 치환을 사용하지 않는다.
