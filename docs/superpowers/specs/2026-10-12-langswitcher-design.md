# LangSwitcher 설계

## 목표와 승인
사용자가 승인한 목표: 표준어 ↔ 문화어 양방향 규칙 기반 변환, 컬러 하이라이트, 웹앱, Electron Windows EXE. 사용자는 추가 질문 없이 끝까지 직접 진행하도록 지시했다. 설계·계획의 추가 승인 단계 대신 아래 결정과 검증 결과를 기록한다. 기존 클라우드 체크아웃은 격리된 `work` 브랜치이므로 별도 worktree를 만들지 않는다.

## 제품
한 화면의 두 편집 패널, 방향 전환, 예문, 파일 가져오기, 결과 복사/저장, 원문과 결과 변경 강조, 변경 목록과 규칙 근거, 검색 가능한 규칙 사전, 규범/평가 안내. 한국어 인터페이스, 반응형, 키보드 접근성, 로컬 처리. 로그인·외부 AI·사용자 텍스트 수집 없음.

## 엔진과 정확도
TypeScript 순수 함수 `convert(text, direction, options): ConversionResult`. 등록 사전과 문맥 조건이 있는 결정적 규칙 모델. 긴 표현 우선, 중복 적용 방지, 원문/결과 UTF-16 위치 보존, NFC 정규화, URL·이메일·인라인 코드·사용자 보호어 보존. 조사 이형태를 함께 처리한다. 고유명사나 문법적으로 중의적인 단어는 전역 음절 치환을 하지 않는다. 역방향은 명시적으로 정의한 대응만 사용한다. 공백·개행·문장부호 보존, 미등록 어휘 유지, 50,000자 입력 상한.

변경 category는 `orthography`, `vocabulary`, `spacing`. 규칙 id, 남측/북측 표현, 설명, 참고 규범, 상태를 기록한다. 철자 대응과 문맥 의존 어휘를 구분하고 어휘 변환을 끌 수 있다. 문화어의 모든 붙여쓰기나 외래어를 자동 결정한다고 주장하지 않는다. 규범집과 한글 맞춤법은 분석 지침이며 원문을 통째로 재배포하지 않는다.

90%는 독립 검수 정답 코퍼스에서 양방향 각각 문장 완전 일치율 ≥ 90%를 목표로 한다. 자체 회귀 예문 통과율을 일반 언어 정확도로 표시하지 않는다. 외부 코퍼스는 별도 JSONL 입력, 평가 도구는 표본 수·방향별 일치율·문자 편집 오류율·실패 예문을 출력한다. 독립 코퍼스가 없으면 목표 달성 여부는 미검증으로 표시한다.

## 구성과 기술
Node >= 22.12, React + TypeScript + Vite, CSS, lucide-react. 엔진은 `src/engine`, 데이터는 `src/engine/rules.ts`, UI는 `src/App.tsx`와 독립 컴포넌트. Vitest는 엔진/평가, Playwright는 Chromium UI/파일/반응형 검증. Electron renderer에는 Node 권한 없음, contextIsolation·sandbox 활성화, 새 창/외부 이동 차단, 로컬 파일만 읽는다. 웹과 데스크톱 동일 정적 빌드. electron-builder로 Windows portable EXE + NSIS installer, 자동 업데이트·서명 키 없음. Linux 교차 빌드 성공과 Windows 실제 실행 검증은 구분한다.

## 실패와 검증
빈 입력, 조합 중 IME, 50,000자 초과, 잘못된 파일 형식/인코딩, 클립보드 실패는 한국어 메시지로 처리. 입력은 기본 저장하지 않으며 설정만 저장 가능. XSS 텍스트는 React 텍스트 노드로 렌더링한다. 테스트: 양방향, 조사, 부분 일치 오변환, 두음 예외, protected spans, 겹친 규칙, 위치, 공백, 반복 적용, 악성 HTML, 평가 분모 및 빈 코퍼스 거부. 앱 빌드·타입 검사·실제 브라우저 기능·모바일 넘침·Windows 산출물 검사까지 실행.

## 산출물
동작하는 앱, 규칙 데이터·규범 분석 문서, 회귀 테스트, 독립 코퍼스 평가 CLI, 정적 웹 `dist`, Windows `release/*.exe`, 재현 가능한 npm lockfile 및 GitHub Windows build workflow. 외부 사이트 배포는 자격 증명 없이 임의로 게시하지 않으며 `dist`를 정적 호스팅에 올릴 수 있게 문서화한다.
